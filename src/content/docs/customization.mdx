You customize LoomiUI with normal CSS variables. Put the variables in your own CSS, and
every LoomiUI component on the page can use them.

There is no config file to edit, no rebuild step, and no Tailwind setup required in your
app.

## Overriding the defaults

Use this variable pattern:

```txt
--loomi-<color>-<shade>
```

`<color>` is one of the palette colors below. `<shade>` is the strength of the color:
`50` is very light, `600` is the normal button color, and `950` is very dark.

For example, this changes the main `primary` color to green:

```css
:root {
  --loomi-primary-600: #16a34a;
  --loomi-primary-700: #15803d;
}
```

After that, every component that uses `color="primary"` picks up your new color. That
includes buttons, inputs, tags, alerts, and other components.

The `:root` selector means "make this available everywhere on the page". LoomiUI
components can read those variables even though they use Shadow DOM.

<loomi-alert type="success" icon="check-circle">
  <strong>Tip:</strong> change the whole color ramp when you can. Components often use
  more than one shade: <code>600</code> for the main color, <code>700</code> for hover,
  and lighter shades for soft backgrounds.
</loomi-alert>

## Per-instance colors

Use the `color` attribute when you want one component to use a specific palette color:

```html
<loomi-checkbox color="red" checked>Critical</loomi-checkbox>
<loomi-checkbox color="green" checked>Resolved</loomi-checkbox>
```

If you later change `--loomi-red-600`, every component using `color="red"` will update.
You do not need to style each component one by one.

## Dark mode

LoomiUI includes a theme switcher component. It lets the user choose light, dark, or
system mode:

```html
<script type="module">
  import "@loomi/theme-switcher/loomi-theme-switcher.js";
</script>

<loomi-theme-switcher></loomi-theme-switcher>
```

The switcher adds a `dark` class to `<html>` when dark mode is active. It also remembers
the user's choice in `localStorage`.

<loomi-tabs>
<loomi-tab label="Use the component" active>

Most apps can just place the component in the header or settings menu:

```html
<loomi-theme-switcher light-text="Light" dark-text="Dark" system-text="Auto"></loomi-theme-switcher>
```

</loomi-tab>
<loomi-tab label="Drive it yourself">

If you are building your own toggle UI, use the helper functions:

```js
import { applyLoomiTheme, getLoomiTheme } from "@loomi/theme-switcher";

applyLoomiTheme("dark"); // "light" | "dark" | "system"
getLoomiTheme(); // reads the persisted choice
```

</loomi-tab>
</loomi-tabs>

To customize dark mode colors, write CSS under `html.dark`:

```css
html.dark {
  --loomi-gray-50: #0f172a;
  --loomi-gray-900: #f1f5f9;
  /* …override whichever tokens your dark palette needs */
}
```

<loomi-alert type="warning" icon="exclamation-triangle">
  To avoid a quick flash of the wrong theme, call
  <code>applyLoomiTheme(getLoomiTheme())</code> as early as possible, before the page
  paints.
</loomi-alert>

## Forking for deeper changes

CSS variables are enough for most apps.

Fork LoomiUI only if you need to change the built-in defaults for everyone or add a new
15th palette color. Those defaults come from `palette.json` during the build, so that is
a source-code change, not a normal app-level customization.
