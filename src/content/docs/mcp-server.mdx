---
title: MCP Server
description: Give Claude Code, Cursor, and other AI tools direct access to LoomiUI's component documentation via MCP.
---

AI coding assistants are good at writing web components, but they can't see LoomiUI's
actual attribute names, default values, or events — so they guess. `@loomidev/mcp-server`
fixes that by exposing this entire documentation site as an [MCP](https://modelcontextprotocol.io)
server your AI tool can query directly, the same way you'd ask a teammate "what
attributes does `<loomi-datepicker>` take?"

It ships every component's docs **bundled into the package** — no network calls, no
access to your filesystem beyond the package itself.

You do not import this package into your app. Your AI editor or assistant starts it in
the background when it needs LoomiUI documentation.

## What it exposes

| Tool | What it does |
| --- | --- |
| `list_components` | Lists every component, optionally filtered by category (`standalone`, `forms`, `content`, `navigation`). |
| `search_components` | Finds components by keyword — matches name, description, and category. |
| `get_component_docs` | Returns the full docs (usage examples, attribute table, events) for one component by name or tag. |

Plus a readable **resource** per component at `loomi://docs/<name>` (e.g.
`loomi://docs/button`), for clients that prefer direct resource reads over tool calls.

## Setup

Before you start, make sure Node.js is installed. The examples below use `npx`, which
comes with npm when you install Node.js.

Add this server config to your AI tool:

```json
{
  "mcpServers": {
    "loomiui": {
      "command": "npx",
      "args": ["-y", "@loomidev/mcp-server"]
    }
  }
}
```

The `"command": "npx"` line tells your tool to download and run the package for you.
The `-y` flag lets `npx` run it without stopping to ask for confirmation.

### Where to put the config

Choose the tool you use, then add the matching JSON to that tool's MCP config file.
If the file does not exist yet, create it. After saving the file, restart the tool so it
can start the `loomiui` server.

#### Claude Code

Add the config to your MCP settings. You can use `.claude/settings.json` in a project,
or run `/mcp` inside an interactive Claude Code session.

#### Cursor

Add this to `~/.cursor/mcp.json` for all Cursor projects, or to your project's
`.cursor/mcp.json` for just one project.

#### Claude Desktop

Add the config to your `claude_desktop_config.json` file.

## Trying it without an editor

Open a regular terminal on your computer, such as Terminal, iTerm, or your editor's
integrated terminal. You can run this from any folder; it does not need to be inside a
LoomiUI project or the app where you plan to use LoomiUI.

```bash
npx -y @loomidev/mcp-server
```

If it starts successfully, it may look like nothing happened. That is expected. MCP
servers communicate over stdio, so this command waits quietly for an MCP client, such
as Claude Code or Cursor, to connect.

Press `Ctrl+C` to stop the test server and return to your terminal prompt.

## Working from source

Most users do not need this. Use the source version only if you are developing LoomiUI
itself or testing an unpublished local change to the MCP server.

For example, if the LoomiUI source workspace lives at `~/Projects/kursor/litail`, build
the server like this:

```bash
cd ~/Projects/kursor/litail/components
pnpm --filter @loomidev/mcp-server build
```

Then point your MCP config at the built file with an absolute path:

```json
{
  "mcpServers": {
    "loomiui": {
      "command": "node",
      "args": ["/Users/your-name/Projects/kursor/litail/components/packages/mcp-server/dist/index.js"]
    }
  }
}
```

You can also start that built server from a consuming app:

```bash
cd ~/Projects/my-app
node /Users/your-name/Projects/kursor/litail/components/packages/mcp-server/dist/index.js
```

That command still uses the local LoomiUI source workspace for the server code; it does
not install anything into `my-app`.

## Using it in your assistant

Once the server is connected, ask your assistant for LoomiUI-specific help:

```txt
Add a LoomiUI date range picker with a max date of today.
```

Your assistant can call `get_component_docs` for `datepicker`, see the real `range`,
`max-date`, and `format` attributes, and write code against the actual component.

## Why this matters

Without the MCP server, an assistant only knows what was in its training data and what
you paste into the chat. With the server connected, it can look up the current LoomiUI
docs before it writes code.
