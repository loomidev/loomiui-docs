`@loomdev-pro/cli` (`loomi-pro`) is the command-line tool for LoomiUI Pro customers. It
scaffolds production starter kits, wires theme presets, adds reusable UI blocks from the
Pro registry, and helps you stay current when templates or packages change.

Unlike a typical npm library install, `loomi-pro` copies **source you own** into your
repository — app shells, route content, theme imports, and block guides land in your
project tree so you can customize, review diffs, and ship without fighting opaque
package internals.

You run the CLI from your terminal. It does not run inside your app at runtime.

## What it does

| Capability | Command | Outcome |
| --- | --- | --- |
| Scaffold a new app | `create` | Full starter kit directory with routes, mock API wiring, and `loomi.json` |
| Configure an existing checkout | `init` | Writes or updates `loomi.json` for your template and framework |
| Apply a theme preset | `theme`, `add theme:*` | Updates `@loomdev-pro/themes` CSS import and config |
| Add UI blocks | `add` | Installs block guides and registry metadata for your template |
| Compare with upstream | `diff` | Shows file diffs against the registry template |
| Validate setup | `doctor` | Checks config, dependencies, and registry auth |
| Upgrade paths | `migrate` | Runs codemods when Pro packages change conventions |

## Prerequisites

Before installing the CLI:

1. **A Pro license** — Solo, Team, or Enterprise. See [Pro licensing](/pro/licensing/) or [browse Pro](/pro/).
2. **Node.js 18+** — the CLI is a Node package; use the same version you run in production.
3. **Private registry access** — your account token must be configured in `.npmrc` so `@loomdev-pro/*` packages resolve.

The CLI itself is published as `@loomdev-pro/cli`. Starter kits depend on
`@loomdev-pro/themes`, `@loomdev-pro/mock-data`, `@loomdev-pro/mock-api`, and
`@loomdev-pro/template-core`.

## Installation

### Configure registry auth

Add your Pro registry credentials to `~/.npmrc` (global) or your project `.npmrc`:

```sh
@loomdev-pro:registry=https://registry.pro.loomiui.com
//registry.pro.loomiui.com/:_authToken=${LOOMI_PRO_TOKEN}
```

Your customer portal provides `LOOMI_PRO_TOKEN` after checkout. Team and Enterprise
plans issue per-seat tokens that can be rotated from the portal.

### Install the CLI

Install globally so `loomi-pro` is on your `PATH`:

```sh
pnpm add -g @loomdev-pro/cli
```

Or run without a global install:

```sh
pnpm dlx @loomdev-pro/cli --help
```

Verify:

```sh
loomi-pro --help
```

You should see `init`, `create`, `add`, `theme`, `diff`, `doctor`, and `migrate` in the
command list.

## Quick start

### Create a new Admin Pro app (Next.js)

Interactive prompts walk you through template, variant, and theme selection:

```sh
loomi-pro create acme-admin
```

For CI pipelines or scripts, pass flags and skip prompts:

```sh
loomi-pro create acme-admin \
  -d \
  --template admin \
  --variant next-react \
  --theme default

cd acme-admin
pnpm install
pnpm dev
```

`create` produces:

- The variant source tree (`src/`, config files, `package.json`)
- Shared route content under `content/` (from the template's canonical route manifest)
- A root `loomi.json` describing your template, variant, theme, and registry
- A theme CSS import in your layout or entry file pointing at `@loomdev-pro/themes/css/<preset>.css`

### Initialize a project you already have

If you cloned or downloaded a Pro starter kit manually:

```sh
cd my-admin-app
loomi-pro init
```

With known values:

```sh
loomi-pro init -d --template saas --variant vite-lit --theme saas-admin
```

`init` detects Next.js vs Vite from `package.json` when possible and can infer the
template from shell file names (`admin-shell.tsx`, `saas-shell.ts`, etc.).

### Validate before you build

```sh
loomi-pro doctor
```

`doctor` reports missing dependencies, framework mismatches, and registry auth problems
before you waste time on a broken install.

## How the registry works

The CLI reads `@loomdev-pro/registry` metadata bundled with the package. The registry
indexes:

- **Templates** — eight shipped combinations (four kits × two framework variants)
- **Themes** — twelve `@loomdev-pro/themes` presets with suggested starter kit pairings
- **Blocks** — dashboard sections (metrics, tables, command palette, etc.) scoped per template
- **Migrations** — codemods for breaking package changes

When you run `add`, `diff`, or `create`, the CLI resolves items from this manifest. Your
project's `loomi.json` records which registry version and template context apply.

## Project configuration

Every Pro project managed by the CLI should have `loomi.json` at the repository root:

```json
{
  "$schema": "https://pro.loomiui.com/schema/loomi.json",
  "template": "admin",
  "variant": "next-react",
  "theme": "default",
  "registry": "@loomdev-pro/registry",
  "css": "src/app/globals.css",
  "aliases": {
    "components": "@/components",
    "pages": "@/app"
  }
}
```

| Field | Description |
| --- | --- |
| `template` | Starter kit family: `admin`, `saas`, `crm`, or `analytics` |
| `variant` | Framework stack: `vite-lit` or `next-react` |
| `theme` | Active theme preset name (matches a file under `@loomdev-pro/themes/css/`) |
| `registry` | Registry package used for `add` and `diff` |
| `css` | Path to your global stylesheet (used by some theme operations) |
| `aliases.components` | Where generated components and blocks should live |
| `aliases.pages` | Where page-level additions are expected (`@/app` for Next.js) |

Run `loomi-pro init -f` to regenerate the file. Use `-f` only when you intend to overwrite.

## Commands

### `init`

Initialize configuration for an existing project.

```sh
loomi-pro init [options]
```

| Option | Description |
| --- | --- |
| `-t, --template <name>` | Starter kit: `admin`, `saas`, `crm`, `analytics` |
| `-v, --variant <name>` | Framework: `vite-lit`, `next-react` |
| `--theme <name>` | Theme preset (see [Theme presets](/pro/themes/theme-presets/)) |
| `-d, --defaults` | Skip interactive prompts |
| `-f, --force` | Overwrite an existing `loomi.json` |
| `-c, --cwd <path>` | Working directory (default: current directory) |
| `-y, --yes` | Skip confirmation prompts |
| `-s, --silent` | Mute non-error output |

**Examples**

```sh
# Interactive — detects framework and shell when possible
loomi-pro init

# Automation-friendly
loomi-pro init -d --template admin --variant next-react --theme default
```

---

### `create`

Scaffold a new project from a starter kit template.

```sh
loomi-pro create <name> [options]
```

| Option | Description |
| --- | --- |
| `-t, --template <name>` | Starter kit |
| `-v, --variant <name>` | Framework variant |
| `--theme <name>` | Theme preset applied on first run |
| `-d, --defaults` | Skip interactive prompts |
| `-c, --cwd <path>` | Parent directory for the new project |
| `-y, --yes` | Skip confirmation prompts |

**Examples**

```sh
loomi-pro create my-crm --template crm --variant next-react --theme fintech -d
loomi-pro create analytics-app --template analytics --variant vite-lit -d
```

**Behavior**

- Copies the variant source tree and shared `content/` routes
- Rewrites `workspace:*` dependencies to published `@loomdev-pro` versions in `package.json`
- Writes `loomi.json` and sets the theme import in `layout.tsx` or `main.ts`
- Sets `package.json` `name` to the directory name you provided

During Pro monorepo development, `create` reads templates from disk when `LOOMI_PRO_ROOT`
is set or auto-detected. Customer releases fetch template tarballs from the private registry.

---

### `add`

Add registry items — theme presets or UI blocks — to your project.

```sh
loomi-pro add [items...] [options]
```

| Option | Description |
| --- | --- |
| `-a, --all` | Add all blocks listed for the current template |
| `-o, --overwrite` | Replace existing files |
| `--dry-run` | Print planned changes without writing files |
| `-p, --path <path>` | Custom install directory for blocks |
| `-c, --cwd <path>` | Working directory |

**Item syntax**

- `theme:<preset>` — apply a theme (same as `loomi-pro theme <preset>`)
- `<block-name>` — add a block guide (e.g. `dashboard-metrics`)

**Examples**

```sh
loomi-pro add theme:fintech
loomi-pro add dashboard-metrics command-palette
loomi-pro add theme:healthcare --dry-run
loomi-pro add --all
```

**Available blocks**

| Block | Description | Templates |
| --- | --- | --- |
| `dashboard-metrics` | Four-up KPI cards with tone variants | admin, saas, crm, analytics |
| `data-table` | Sortable table wired to mock API data | admin, saas, crm, analytics |
| `activity-feed` | Timeline-style activity list | admin, crm |
| `command-palette` | Keyboard-driven command overlay | all |
| `filter-builder` | Rule-based filter builder for reports | admin, analytics |

Use `--dry-run` before `--overwrite` when updating files you may have customized.

### `theme`

Apply or list theme presets from `@loomdev-pro/themes`.

```sh
loomi-pro theme [name] [options]
```

| Option | Description |
| --- | --- |
| `--list` | Print all preset names and labels |
| `--dry-run` | Show import path changes without writing |
| `-c, --cwd <path>` | Working directory |

**Examples**

```sh
loomi-pro theme --list
loomi-pro theme healthcare
loomi-pro theme enterprise-neutral --dry-run
```

**Theme presets**

| Name | Label | Suggested kit |
| --- | --- | --- |
| `default` | Loomi Default | admin |
| `saas-admin` | SaaS Admin | saas |
| `fintech` | Fintech | crm |
| `developer-tools` | Developer Tools | analytics |
| `healthcare` | Healthcare | any |
| `education` | Education | any |
| `creator-tools` | Creator Tools | any |
| `ecommerce-admin` | E-commerce Admin | any |
| `enterprise-neutral` | Enterprise Neutral | any |
| `high-contrast` | High Contrast | any |
| `marketing-growth` | Marketing Growth | any |
| `legal-compliance` | Legal Compliance | any |

Browse live previews on [Theme presets](/pro/themes/theme-presets/).

`theme` updates the CSS import in your root layout or entry file and saves the preset
name to `loomi.json`.

---

### `diff`

Compare local project files against the registry template for your configured kit.

```sh
loomi-pro diff [target] [options]
```

| Option | Description |
| --- | --- |
| `-c, --cwd <path>` | Working directory |

**Examples**

```sh
# Compare all comparable src files
loomi-pro diff

# Narrow to files matching a path fragment
loomi-pro diff admin-shell
```

Output is a unified diff per changed file. Use this after Pro updates to see what
changed upstream before merging or re-applying blocks.

When template source is unavailable (no `LOOMI_PRO_ROOT` and no registry tarball),
`diff` prints a configuration summary instead of file diffs.

---

### `doctor`

Validate project health.

```sh
loomi-pro doctor [options]
```

Checks:

- `loomi.json` exists and parses against the schema
- Required `@loomdev-pro/*` packages appear in `package.json`
- Detected framework (Next.js vs Vite) matches `loomi.json` `variant`
- `@loomdev-pro:registry` auth is present in `.npmrc`

Exit code is non-zero when issues are found — useful in CI after scaffolding.

---

### `migrate`

Run codemods when Pro packages introduce breaking changes.

```sh
loomi-pro migrate [migration] [path] [options]
```

| Option | Description |
| --- | --- |
| `-l, --list` | List available migrations |
| `-c, --cwd <path>` | Working directory |
| `-y, --yes` | Skip confirmation prompts |

**Examples**

```sh
loomi-pro migrate --list
loomi-pro migrate theme-imports
loomi-pro migrate mock-api src
```

| Migration | Description |
| --- | --- |
| `theme-imports` | Normalize `@loomdev-pro/themes` CSS import paths to the current export format |
| `mock-api` | Align mock API imports with `@loomdev-pro/mock-api` route modules |

Always commit or back up your code before running migrations.

## Starter kits

| Template | Variants | What you get |
| --- | --- | --- |
| `admin` | vite-lit, next-react | Dashboard, users, teams, roles, billing, activity, reports |
| `saas` | vite-lit, next-react | Auth flows, onboarding, members, billing, usage, API keys |
| `crm` | vite-lit, next-react | Pipeline, leads, contacts, companies, deals, tasks, import |
| `analytics` | vite-lit, next-react | Overview, metrics, segments, cohorts, exports, alerts |

Each variant includes:

- A client-side or App Router shell with navigation driven by `content/routes.json`
- Mock API routes backed by `@loomdev-pro/mock-data` fixtures
- Pro component registration via `@loomdev-pro/template-core`
- Theme CSS variables from your chosen preset

See the full catalog on [Pro templates](/pro/templates/).

### Framework variants

**`next-react`** — Next.js App Router with a catch-all route, React bridges for web
components (`pro-elements.tsx`), and mock API at `src/app/api/[...path]/route.ts`.

**`vite-lit`** — Vite SPA with Lit components, client-side routing in `src/main.ts`, and
mock API via the `@loomdev-pro/mock-api/vite` plugin.

Pick the variant that matches your team's stack. The CLI keeps the same routes and mock
data across both — only the rendering layer differs.

## Workflows

### CI: scaffold, validate, and build

```sh
loomi-pro create ci-admin -d --template admin --variant next-react --theme default
cd ci-admin
loomi-pro doctor
pnpm install --frozen-lockfile
pnpm build
```

Add `loomi-pro doctor` to catch missing registry auth or dependency gaps before install.

### Switch brand theme in an existing app

```sh
loomi-pro theme fintech --dry-run   # preview
loomi-pro theme fintech
loomi-pro doctor
```

Restart your dev server so layout imports reload.

### Review upstream template changes

After a Pro release:

```sh
loomi-pro diff
loomi-pro add dashboard-metrics --dry-run
```

Merge intentional customizations manually, or use `--overwrite` when you want the registry
version to replace local files.

### Upgrade import paths after a package release

```sh
git commit -am "checkpoint before migration"
loomi-pro migrate theme-imports
loomi-pro migrate mock-api
loomi-pro doctor
```

## Environment variables

| Variable | Description |
| --- | --- |
| `LOOMI_PRO_ROOT` | Absolute path to the Pro monorepo. Used by `create` and `diff` when developing templates locally. Auto-detected when the CLI runs inside the monorepo. |
| `LOOMI_PRO_TOKEN` | Common name for the registry auth token referenced in `.npmrc` examples |

## Troubleshooting

**`doctor` reports missing registry auth**

Confirm `@loomdev-pro:registry` and your auth token line exist in `~/.npmrc` or the project
`.npmrc`. Tokens expire when seats rotate — generate a new one from the customer portal.

**`create` cannot find template source**

Set `LOOMI_PRO_ROOT` to the Pro monorepo root, or use a published CLI release that
fetches registry tarballs (customer installs).

**Framework mismatch in `doctor`**

Your `loomi.json` `variant` does not match installed tooling. Re-run
`loomi-pro init -f` with the correct `-v` flag, or align `package.json` dependencies.

**Theme import did not update**

Ensure your layout file imports `@loomdev-pro/themes/css/<preset>.css`. The CLI looks
for `src/app/layout.tsx` (Next.js) or `src/main.ts` (Vite).
